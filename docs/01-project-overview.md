# 專案總覽與功能規格

> 本文件依另一個 Claude 對話中產生的原始規劃內容整理重建，非逐字複製；若需要對照最原始版本，請參考該對話輸出的 `draw-guess-party-docs/01-project-overview.md`。

## 專案定位

線上多人即時畫圖猜謎派對遊戲，姊妹專案為「音樂猜歌」。核心玩法：一人畫圖、其他人即時看著筆畫同步出現並搶答猜題。

## 三種遊戲模式（GameMode）

| 模式代號 | 名稱 | 規則 | 優先順序 |
|---|---|---|---|
| `DRAW_GUESS` | 你畫我猜 | 輪流一人畫圖，其他人聊天室搶答猜題目 | v1，優先實作 |
| `FRAGMENT_DRAW` | 共同拼圖畫 | 畫布依人數切格，每人畫自己那一格，公布時前端合成成一張完整圖 | v2 |
| `DRAW_TELEPHONE` | 畫圖接龍 | 至少 3 人，每一位先看前一棒的畫、猜測，再畫下自己的猜測（不是交替文字/圖片），最後一位只猜、猜完直接公布整條鏈給大家欣賞 | v2（已完成） |

三種模式共用同一套「即時繪圖引擎」（畫布、筆刷、同步機制）與「房間系統」，差異在於：誰看得到畫布、有沒有「猜」這個動作、計分邏輯是否存在。

## 房間系統

- 房主建立房間，取得 6 碼加入代碼，其他人輸入代碼加入
- 房主可設定：遊戲模式、每輪限時秒數、題庫分類/難度篩選（`DRAW_GUESS` 用）
- 玩家清單即時同步（誰在房間裡、誰是房主、目前分數）
- 房主可開始遊戲、提前結束、（`DRAW_GUESS`）投票跳過卡關的題目——沿用音樂猜歌專案「全員投票才流局」的設計（本輪程式碼尚未實作投票跳題）

## 題庫（DRAW_GUESS 用）

- 題目為單一詞語，分類（例如：動物、電影、成語）與難度（易/中/難）
- 房主建立比賽時可依分類/難度篩選題庫
- 需要一個題庫管理後台（比照音樂猜歌專案的 `/admin`，HTTP Basic Auth 保護），可新增/編輯/刪除題目，也可批次匯入 CSV

## 裝置與輸入

- 手機優先：畫布支援觸控（touch）與滑鼠（pointer）統一以 Pointer Events API 處理
- 猜題的人主要用聊天室打字搶答，介面需清楚區分聊天訊息與系統訊息

## 開發階段總覽

詳見 `05-roadmap.md`。順序為：環境建置 → 房間系統 → 即時繪圖引擎 MVP → DRAW_GUESS 模式 → 題庫管理後台 → FRAGMENT_DRAW 模式 → （stretch）DRAW_TELEPHONE 模式 → 行動裝置優化與部署。

**本次整合實作完成度**：Phase 0（環境／專案骨架）、Phase 1（房間系統）、Phase 2（即時繪圖引擎 MVP）、Phase 3（DRAW_GUESS 完整流程：抽題、輪流指定畫圖者、猜對自動公布並進下一輪）、Phase 4（題庫管理後台）、Phase 6（DRAW_TELEPHONE 畫圖接龍）已完成並通過端對端測試。Phase 5（`FRAGMENT_DRAW`）、PostgreSQL/Prisma 資料落地、部署尚未實作。

## 視覺設計

白色背景為主的手繪桌遊卡牌風格：純白底、墨色文字、珊瑚橘主色，卡片與按鈕統一用「粗墨線外框 + 偏移實色陰影」，按下時位移回饋做出「真的按下去」的觸感。畫筆調色盤擴充為 16 色蠟筆盤，依色相排列。詳細色彩／間距 token 見 `app/globals.css`。

受限於部署沙盒環境無法連外抓取 Google Fonts 等字型 CDN（網路白名單限制），字體選用系統字體（`PingFang TC` / `Microsoft JhengHei` 等）疊加字重與字級差異做出標題辨識度，未使用自訂 Web Font。
